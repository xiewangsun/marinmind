## 1. 评估范围与方法

- **范围**：`src/home/`（主页四页 + 卡片预览弹窗）、`src/reader/`（阅读器工具行/侧栏/高亮体系）、`src/mindmap/`（画布/节点/header）、`src/review/`（闪卡正反面/评分/溯源）、`src/ui/view-mode-bar.ts`，以及 `styles.css` 全量。
- **方法**：三路只读调查交叉印证——①styles.css 设计体系逐段盘点（令牌/字面色/排版/圆角/动效/可访问性/结构健康）；②四视图 TS 层 UI 结构与文案盘点（结构/内联样式/文案/图标/交互态/aria）；③产品文档 UX 调查（定位/迭代史反映的用户口味/既有挂账）。技术疑点（radius 统一安全性、字号 rem 化波及面、emoji 换图标改动量）经源码二次核实。
- **不在范围**：功能/性能/布局能力类挂账（译文留白折叠、三窗格、脑图键盘操作、热力图等）——归《后续优化方向.md》管，见第八章分工。

## 2. 结论摘要

**总判词：「三套半皮肤 + 一个未完成的高光」。**

| 视图 | 皮肤 | 主色来源 |
|---|---|---|
| 主页 | Linear 深浅双主题孤岛 | 自有 23 变量×2（`#0d0e11`/`#ffffff` 底、`#5e6ad2` 紫），强制 Linear 色、覆盖 radius 为 4/6px |
| 阅读器/脑图/复习 | Obsidian 原生 + MN3 四色线稿 | 宿主全局变量 + `--mm-hl-*` 功能色（血缘最近的一组） |
| 各弹窗 | 跟随宿主 | 宿主全局变量 |

「未完成的高光」指 `--mm-hl-line/--mm-hl-tint` 摘录四色令牌：**全文件最好的令牌设计**（形态规则只消费变量、`data-color` 驱动全员变色），且技术上已贯穿三视图（阅读器高亮 → 脑图节点头 tint → 复习遮挡块色）——但字面值断裂成四源、主页完全缺席。这正是签名元素的现成载体。

**三项决策预告**（详细论证见后续章节）：

1. **签名元素定案「墨色随卡走」**（第五章）：阅读时选的摘录墨色跟着卡片走遍四视图。数据层零新增（`Card.color` 早已存在），落地顺手偿清最大令牌债。
2. **主页 Linear 方向保留**：用户多轮迭代确认的既定方向（㊲-㊸），不推翻；差异化靠签名元素而非重刷主页。
3. **radius「双声道」为有意决策**：主页 6px（Linear 声音）vs 宿主视图 8px（复习大卡软朗观感合理），不统一、写档防后人当漂移误修（P2-3）。

**质量底线缺口是当前最实际的账**：全文件零 `:focus-visible`、零 `prefers-reduced-motion`、`--text-faint` 承载真实信息约 6-8 处对比度不足（代码注释自认此问题但只修了搜索框一处）、12 处黑阴影不随浅色主题减弱（P0 全清）。

## 3. 设计体系现状盘点

### 3.1 三层令牌架构

```
┌─ 第 1 层：主页 Linear 双主题（.marinmind-home-dark / -light，styles.css 2329-2378）
│    23 变量逐键镜像：background-×4 / modifier-×4 / text-×6 / interactive-×4 / radius-s=4 / radius-m=6
│    同名键覆盖 Obsidian 全局变量 → auto 态摘类回落宿主主题（有护栏的分裂）
├─ 第 2 层：宿主全局变量（阅读器/脑图/复习/弹窗全部消费）
│    --background-* / --text-* / --interactive-* / --radius-* / --font-ui-*
└─ 第 3 层：MarinMind 功能色令牌（唯一自建令牌，挂在 data-color 元素上）
     --mm-hl-line（线稿色）/ --mm-hl-tint（悬停淡底）：四主色 + 四存量旧色相 + 黄兜底，共 9 组
     --mm-occ-line（复习遮挡色，JS 经 highlightLineColor 注入，CSS 消费）
```

主页没有私有键名（聪明——复用语义键即插即用），但也意味着它**劫持了全局键语义**：radius-m 被覆盖为 6px，与宿主默认 8px 构成同产品两档（见 3.4）。

### 3.2 字面色分布（铁律执行情况）

- **主页分区（2380-3104）零字面色——「主页样式只准引用变量」铁律成立，无违例**。深浅两覆盖块是铁律的合法例外（令牌定义本体）。
- 块外约 61 处字面色，其中最大问题是**摘录色系四处字面源**（同一体系写了四遍）：

| 源 | 位置 | 形式 | 问题 |
|---|---|---|---|
| ① `--mm-hl-*` 变量定义 | styles.css:275-315 | rgba(217,169,22,0.95) 等 | 令牌本体（正当） |
| ② 脑图节点头 tint | styles.css:1195-1227 | rgba(232,197,58,0.25) 等 8 色 | 重复同源色值，未抽变量 |
| ③ 拖卡 ghost 色条 | styles.css:1427-1457 | #e8c53a 等 8 个 hex | 同色换 hex 记法 |
| ④ 工具行色点 | styles.css:415-435 | #e8c53a 等 4 个 hex | 同上 |

同一「绿」= `rgba(90,171,90,…) / #5aab5a`（同值两形）四处出现；pink 在 CSS 变量（`rgba(236,72,153,…)` = #ec4899）与 ghost/TS 旧色表（`#d96a9c`）是**两个不同色值**；yellow 的 tint 基底（#ffd540 系）与 swatch 基底（#e8c53a）也不一致。这是 P1-a 的靶子。

- 其余字面色：12 处 `rgba(0,0,0,0.15~0.35)` 黑阴影（142、349、422、642、1143、1164、1261、1395、1483、1593、1632、1872）**不随浅色主题减弱**；AI 弹窗徽标 `#9a5fc0`/`#8a7418`（2198/2203）暗色下对比度接近失效；中性灰填充 4 处（遮挡占位/脑图框架/节点头兜底）属低风险。

### 3.3 排版

- **font-family 全文件仅 1 处声明（inherit）**——零自定义字体，全部继承 Obsidian 界面字体。对 Obsidian 插件这是正确姿态；「排版个性」应从字阶/字重/字距的纪律性来（主页已用 letter-spacing 0.02/0.06em + 600/700 字重做了 Linear 式签名），而非引入字体族。
- **三套字号体系并存**：
  - 主页 px 标尺：11/12/13/16/22px 共 23 处——**不响应 Obsidian「界面字号」设置**（P2-4）；
  - 其它视图 Obsidian 令牌：`--font-ui-smaller` ×38（绝对主力）+ small/smallest/medium；
  - 复习 em 放大：卡片正文 1.15em/1.25em/1.6em + 行高 1.7（阅读态最松，语义合理）。
- 字重基本成体系（600=标题态 ×9、700=主页大字 ×3），个别 `bold` 与变量引用混用（809 vs 731）。

### 3.4 圆角与间距

- `--radius-s`（4px）×36 处绝对主力 + 两处 `calc(var(--radius-s) - 1px)` 内缩（精致细节）+ 999px 胶囊 ×6 + 50% 圆 ×3。
- **radius-m 双声道**：主页覆盖 6px（统计砖 2513、书架 2953）vs 宿主默认 8px（复习大卡 754、溯源块 703、节点编辑浮层 1482）。3 处消费、2px 差异、不同屏对比——**接受为有意决策**（P2-3 落档）。
- 笔误：styles.css:1803 `var(--radius-s, 6px)` 兜底值与全文件其余 13 处 `4px` 约定不一致（Obsidian 恒定义该变量，零视觉变化，纯一致卫生）。
- 间距两套标尺：主页 px（gap 2/4/6/8/12/24，严格 4 网格，Linear 式纪律）vs 其它视图 em（0.35/0.4/0.5/0.6/0.75/1em 碎值 + px 混排）。前者是纪律、后者是惯例，不强推统一。

### 3.5 动效

- 3 个 `@keyframes`：录音红点呼吸 1.2s 无限（1606）、高亮定位闪烁 0.75s×2（1759，阅读器/脑图共用）、封面加载呼吸 1.2s 无限（2990）。
- 13 处 transition **全部 ≤0.15s**（主页 9 处全 0.1s）——Linear 式快反馈，克制，是保留项。
- **零 `prefers-reduced-motion`**：两个 1.2s 无限循环对动效敏感用户无豁免（P0-2）。
- 全插件缺一个「编排时刻」（frontend-design：一个精心编排的瞬间 > 散落效果）——由签名元素 P1-c 的翻面墨线承担。

### 3.6 可访问性/质量底线

| 项 | 现状 | 级别 |
|---|---|---|
| 键盘焦点环 | **零 `:focus-visible`**；唯一 `:focus` 是主页搜索框且先 `outline:none`（2797） | P0-1 |
| 减弱动效 | 零支持 | P0-2 |
| `--text-faint` 对比度 | 全文件 27 处；约 6-8 处承载真实信息（节点折叠计数 1299、分页信息 2857、脑图连线 stroke 1120、复习 hint 917、脑图 hint 1368、AI 页码 2218、主页行 meta 2671-2673）。styles.css:2785 注释自认「--text-faint 仅 40% 透明度看不清」但只在搜索框占位符修了 | P0-3 |

### 3.7 结构健康度（好的一面）

- `!important` **0 处**；2 处特异性把戏（2786 搜索框三祖先压主题、2695 folders-hidden 压媒体查询）均有注释说明。
- z-index 8 值（2/3/4/10/20/var(--layer-popover,100)）分层克制，无军备竞赛。
- 命名高度成体系：`marinmind-` 前缀 + 视图二级前缀（home/mm/review/toc/autoex/…）+ `is-*` 状态 + `data-color/data-grade` 驱动。
- 重复配方（收敛对象，P2-2）：分段控件 4 套（view-mode 71-102 / toc-tabs 1906-1937 / home-view-toggle 2887-2924 / review-ctx-tab 667-686）、按钮配方 6 套、999px 胶囊徽标 6 套、`-webkit-line-clamp:3` 四联（1246/1268/1409/1700）。

## 5. 签名元素方案

frontend-design 核心要求：「花胆量在一个地方」——一个可辨识的签名元素，其余保持克制。

### 5.1 候选一（推荐）：「墨色随卡走」

**概念**：用户在阅读器划下摘录时选的那一笔墨色（浅黄/浅绿/浅蓝/浅红），就是这张卡的身份——不是装饰色，是**用户自己的知识分类**。让这抹墨从阅读器下划线出发，出现在脑图节点头、拖卡 ghost、主页卡片行与预览弹窗（墨点）、复习卡（四缘墨框），直至评分换卡时刻——「你读书时定的颜色，记得你读过的东西」。

**为什么它足以成为签名**：
- **扎根主题**：色源自「批注墨水」这个主题世界本身，非通用 SaaS 强调色；
- **有语义**：全代码库唯一「用户选择的颜色」而非「系统分配的颜色」；
- **跨全四视图**：技术上血缘已通三视图（阅读器 → 脑图 tint → 复习遮挡 ㊿-C），只差主页与复习普通卡补位；
- **顺手偿清最大令牌债**：签名落地 = 四处字面色收敛为单一令牌源（P1-a 是前置）；
- **数据层零新增**：`Card.color`（types.ts:70）早已存在；`highlightFallbackColor`（highlight-colors.ts:47-60）对 null 色卡按形态回退（手写绿/照片语音红/其余黄），与阅读器 canvas 描边同源——补位渲染不产生任何新决策；存量旧色卡（teal/orange/purple/pink）天然按原色相透传。

**落地三步**（即第六章 P1-a/b/c）：

| 步 | 内容 | 视图增量 |
|---|---|---|
| P1-a 令牌收敛 | `--mm-hl-*` 定义块的选择器列表扩为同时匹配节点头/ghost 色条/工具色点（三者本就挂 data-color），三处字面源改消费变量 | 观感不变（同值），代码单源化 |
| P1-b 补位主页 | 主页卡片行标题前 6-8px 墨点（`data-color=highlightFallbackColor(card)`）；预览弹窗标题左缘 3px 墨线或 meta 行墨点 | 主页只 `var(--mm-hl-line)` 引用，**不破分区铁律**（变量定义块在阅读器色彩分区，块外） |

## 第二轮：组件级细粒度评审（R2，2026-08-31）

上轮（第 1-9 章）解决**设计体系级**问题（令牌/可访问性/一致性）；本轮按用户确认的范围做**组件级**细粒度评审——溢出 / 截断 / 长文本 / 窄窗格 / 信息冗余，覆盖主页 + 阅读器 + 脑图 + 复习 + 全部弹窗。准绳不变（附录 A 8 条），落点集中在第 6 条质量底线的「响应式」维度，并有一个本轮固化的结构性认识：

> **插件 UI 的响应式短板不在视口宽度，而在 split 窗格宽度。** styles.css 全部媒体查询基于视口，分屏半宽/四分之一宽窗格不触发任何断点——容器级弹性（flex-wrap / min-width:0 / 截断三件套 / 限高滚动）是唯一可靠的兜底手段。

### R2.1 方法与判定基线

- **三路只读调查**：① styles.css 逐 flex 行「三件套」（`white-space:nowrap + overflow:hidden + text-overflow:ellipsis` + flex 子项 `min-width:0`）齐备性审计；② 双代理分别盘点「主页+弹窗」「阅读器+脑图+复习」TS 层每个列表行/下拉/徽标/菜单项的长文本行为与数据源上界；③ 边界条件走查（split 半宽/四分之一宽、长 CJK 标题、无界数据源 = 书名/图名/分类路径（≤120 字符）/卡片标题/批注/摘录全文/库外绝对路径）。
- **判定基线**（本轮新增护栏，与第七章并列沿用）：折行不溢出 = 低风险可接受（信息保真优先）；横向溢出 / 裁切不可达（overflow:hidden 无滚动）/ 爆高数屏 = 缺陷必修；同型不同标（一处截断一处不截）记**双标账**统一。
- **已验证安全位**（不再列问题）：阅读器目录/书签条目三件套、AI 摘录预览行省略 + 列表 320px 限高、翻译原文/译文 160px 限高滚动、脑图节点三栏（头省略/中栏三行/批注三行截断）、媒体长边 `max-height:24em`、拖拽 ghost 2 行截断、留白胶囊 16em + 右缘左翻、复习 scope 徽标 12em 封顶、溯源路径 wrap + 16em、统计四格 grid、TOC 面板 `min(300px,85%)`、菜单头截断正例（脑图 30 字 / 媒体 24 字）。
- **保留取舍**：复习评分四钮极窄时钮内文字折行两行——`flex:1` 折行比 `nowrap` 溢出**安全**，保留现状是正确取舍（记判定，非挂账）。

## 附录 A：评审标准（frontend-design 凝练版）


1. **扎根主题**：视觉决策源于主题自身世界（MarinMind = 阅读·摘录·记忆·知识卡片），而非通用模板；
2. **设计令牌**：命名色板 / 字体角色 / 布局概念 / **签名元素**——唯一让人记住的点，「花胆量在一个地方」；
3. **排版承载个性**：字阶/字重/字距的纪律性（Obsidian 插件语境下不引字体族）；
4. **结构即信息**：编号/标签/分隔必须编码真实语义，不做装饰；
5. **动效克制**：一个编排时刻 > 散落效果；
6. **质量底线**：响应式、键盘焦点可见、prefers-reduced-motion、对比度——不达标不算完成；
7. **文案即设计材料**：主动语态、空态=行动邀请、错误不模糊；
8. **避免模板脸**：AI 默认三件套（奶油底+衬线+赤陶 / 近黑底+单一荧光色 / 报纸风）是默认而非选择——主页 Linear 近黑+紫接近模板 #2，但属用户既定方向保留，靠「墨色随卡走」这一主题化签名差异化。
