# 发布与上架流程

> 记录 MarinMind 从本地仓库到 Obsidian 官方社区插件市场上架的完整流程，
> 以及上架后的日常发版节奏。首次执行于 1.0.0 发布（批次 132）。
> 官方文档：[Submit your plugin](https://docs.obsidian.md/plugins/releasing/submit-plugin)、
> [Submission requirements](https://docs.obsidian.md/community-directory/submission-requirements-for-plugins)。

## 总览

```
本地文件定稿 → GitHub 建仓推送 → CI 绿 → 打 tag v1.0.0（release.yml 自动发版）
→ BRAT 真实安装内测 → community.obsidian.md 提交 → 自动审查 → 人工审核
→ 上架 → 论坛/Discord 公告
```

关键事实（2025-09 核实）：

- 社区插件提交入口已从「给 obsidian-releases 提 PR」改为
  **community.obsidian.md 网页门户**（Obsidian 账号登录 + 关联 GitHub 账号）。
- 门户读取**默认分支 HEAD 的 manifest.json** 验证；用户安装时从
  **GitHub Release**（tag 与 manifest version 一致）下载 `main.js` /
  `manifest.json` / `styles.css` 三件套——所以仓库 manifest 与 release
  资产两处都必须正确。
- 人工审核积压数周至数月，门户开发者面板可查进度。
- 只需提交初始版本；上架后新版本打 tag 发 release，Obsidian 自动向用户
  推送更新，无需再动社区目录。

## 一、发布文件清单（每次发版前核对）

| 文件 | 要求 |
| ---- | ---- |
| `manifest.json` | version 遵循 `x.y.z`；description 英文、动作开头、句号结尾、≤250 字符、无 emoji；id 唯一且不含 "obsidian"；用 Node/Electron API 必须 `isDesktopOnly: true`；无捐赠渠道不得留 fundingUrl |
| `versions.json` | 含 `{ "<version>": "<minAppVersion>" }` 映射（release.yml 也会兜底回写） |
| `main.js` | 由 CI 干净构建产出（本地 main.js 已 gitignore） |
| `styles.css` | 仓库根目录、随 release 上传 |
| `README.md` | 英文为主：用途 + 用法 + 安装三通道 + **数据存储披露** + **网络使用披露**（AI/搜索/翻译/OCR）+ 链接中文教程 |
| `LICENSE` | MIT（Copyright (c) 2026 xiewangsun） |
| `package.json` | version 与 manifest 同步 |

## 二、首次上架流程（1.0.0 已执行至「文件定稿」）

1. **挂账收尾**：手动验收未提交批次 → 按批次风格提交。
2. **GitHub 建仓**：创建公开仓库 `xiewangsun/marinmind`（与插件 id 一致），
   `git remote add origin` + push main。本机无 gh CLI 时网页创建。
3. **CI 验证**：确认 push 后 ci.yml（lint / format / test / build）跑绿。
4. **打 tag 发版**：
   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```
   release.yml 自动：校验 tag ↔ manifest 版本一致 → npm ci → build →
   versions.json 兜底同步（回写 main）→ 创建 Release 附三件套。
5. **核对 Release**：GitHub Release 页应见 `main.js`（约 1.4MB）/
   `manifest.json` / `styles.css` 三个资产，tag = manifest version。
6. **BRAT 内测**：测试库装 BRAT → Add Beta plugin 填 `xiewangsun/marinmind`
   → 验证安装启用、核心链路（导入 → 摘录 → 脑图 → 复习）。
   有问题：修复 → manifest 版本递增 → 重新打 tag 发版（BRAT Check for
   updates 复验）。
7. **社区目录提交**：community.obsidian.md 登录（Obsidian 账号）→ 关联
   GitHub 账号 → 添加插件。
8. **处理审查反馈**：自动审查有错则修仓库 + 发递增版本新 release；
   人工审核期间耐心等待（面板可查状态）。
9. **上架公告**：论坛 [Share & showcase](https://forum.obsidian.md/c/share-showcase/9)
   发帖 + Discord `#updates`（需 developer 角色）。

## 三、后续版本迭代（日常发版节奏）

自动化已闭环，只需四步：

1. 改 `manifest.json` 的 `version`（递增语义化版本号）。
2. 补 `versions.json` 对应条目（minAppVersion 不变则同值）。
3. 提交并推送。
4. `git tag vX.Y.Z && git push origin vX.Y.Z` → release.yml 自动发版，
   Obsidian 向用户推送更新。

## 四、注意事项（审核常见拒绝原因）

- 网络请求必须在 README 披露用途（本插件：AI 问答、联网搜索、翻译、OCR
  引擎下载——全部用户主动触发、密钥用户自填）。
- 数据存储位置必须可解释（本插件：vault 内 `MarinMind/` 目录，可配置）。
- 不得有混淆代码（esbuild 标准打包无混淆 ✅）；仓库源码可读（✅）。
- 命令 ID 不含插件 id 前缀（Obsidian 自动加前缀）。
- tag 必须与 manifest version 完全一致（release.yml 第一步强校验）。
