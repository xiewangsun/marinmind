**样式体系（styles.css）**：文件头「全局：设计令牌与质量底线」分区承载跨视图基线
（前端设计 P0）——`--mm-shadow-sm/-lg/-page/-panel/-drop-shadow` 五档阴影令牌（挂
body，`body.theme-light` 覆盖为浅色档，原 11 处字面黑阴影归并消费）+ 插件域
`:focus-visible` 键盘焦点环（双选择器特异性 (0,3,1) 压过既有 outline 覆盖）+
`prefers-reduced-motion` 豁免（录音/封面呼吸置 none、跳原文定位闪烁退静态 accent
描边——承载定位信息不可简单关闭）。主页可点 div 经 home-pages 的
`enableKeyboardActivation`（role="button" + tabIndex + Enter/Space 触发 click）键盘化；
`--mm-hl-line/-tint` 摘录色令牌 P1-a 起收敛为**单源**——定义块 `:is()` 列表覆盖九类
消费者（阅读器高亮/拖框/套索预览/脑图节点头/拖卡 ghost/工具色点/主页墨点/预览弹窗/
复习卡），卡片身份色一律 `data-color=highlightFallbackColor(card)`（null 按形态回退、
旧色相透传、var fallback 兜空值）；复习卡顶缘墨线 `::before` 0.3s 从左展开为全插件
唯一编排时刻（reduced-motion 退静态）；tint alpha 统一 0.2、pink 统一 #d96a9c 系
（校准依据见评估报告 5.1）；主页变量覆盖块见主页章节；主页分区铁律不变（墨点样式
只引用变量）。

## 数据层（㉚ Markdown 文件存储）

- **总体形态**：全部数据（文档/卡片/复习状态/链接/脑图/书签）存为数据根（默认
  vault 内 `MarinMind/`，可经设置配置到桌面绝对路径，见「设置与存储定位」）下的
  **Markdown 文件**——**每书一文件**（`<书名>.md`）、**一图一文件**（`脑图/<图名>.md`）、
  媒体附件 `assets/<uid>.<ext>`、无主卡兜底 `未归类卡片.md`、按日聚合复习日志
  `复习日志.md`（66：reviews/newCards/again 三计数，日键 yyyy-mm-dd 本地时区）、
  分类/卡组显式清单 `分类.md`/`卡组.md`（76：每行 `- 路径`，行权威可手编——记录
  用户显式创建的空分组，清空即删文件）。
  用户可在 Obsidian 中直接
  浏览/搜索/编辑这些文件（frontmatter `marinmind: book|mindmap|reviewlog|folders|decks` 标识文件类型）。
  旧 SQLite 方案（schema v1-v8 迁移史）已退役，仅保留读取能力用于旧库/旧备份导入（见下）。

## 阅读视图

- **渲染**：`loadPdfJs()` 复用 Obsidian 内置 PDF.js，不自带 pdfjs-dist；
  只用 getDocument/getPage/getViewport/render/destroy/getTextContent 稳定 API 面，
  外加目录三件套 getOutline/getDestination/getPageIndex（㉓；均为公开 API，
  局部类型 `pdfjs-types.ts`）。**共享解析缓存（㊳ `pdf-cache.ts`）**：
  `acquirePdf(key, bytes)` 引用计数复用同一 PdfDocument（命中校验字节数，
  不符销毁重建；并发同 key 单飞）——阅读器/AI 摘录弹窗/复习溯源缩略图共用
  同一次解析，双标签二开秒出；`retainPdf` 短期借用、`PdfHandle.release()`
  幂等（归零才 destroy）。
- **文档形态三态（㊼ docKind）**：`DocKind = "pdf" | "md" | "epub"`（docKindOf 按扩展名
  判定）+ `isReflowDoc` getter（≠pdf，共享无位图/固定栏宽/pdfOnlyActions 隐藏分支）+
  `pageWord` getter（epub「章」其余「页」）；`paths.ts` 的 `docExtOf`/`pageWordOf`
  为全库统一判定点（视觉消费方短路/文案分词）。
- **Markdown 文档阅读（㊻-B 核心版）**：库内 md 可当文档打开——选择器默认收
  pdf+md+epub 且**排除数据根**（`plugin.dataRootRelPath` 公开化判别，防数据根卡片文件
  被当文档打开引发 upsert 撞名/modify 双路由；文档管理重关联传 extensions:
  [源扩展名]——跨格式重关联拒绝，pdf 页码 vs epub 章号语义错乱宁拒不赌）；
  `loadFromPath` 判定 .md → `vault.cachedRead` 取文本（**不 acquirePdf**，
  `this.pdf` 保持 null——AI 摘录/懒渲染/尺寸巡检/快照回填的 pdf 守卫天然降级）；
  totalPages=1、列宽 820×scale（computeFitScale 上限 1，窄窗格缩列宽），占位高
  1000px 渲染后由内容高度接管；`PageView.setReflowContent` 内容容器替换文本层位
  （挂 `markdown-preview-view` 类吃 Obsidian 原生排版，layout 只定宽高内容驱动，
  CSS **必须关页容器 content-visibility:auto**——auto 会把离屏自动高度内容折叠回
  1000px 占位导致滚动跳变）；`MdDocument.renderInto`（MarkdownRenderer 异步分块，
  loadToken 守卫丢弃换文档后的过期渲染 + internal-link 点击委托 openLinkText）→
  `outlineFromDom` 抽标题树（栈算法：级别回落上溯/跳跃挂前标题/空白跳过；前序
  遍历回填 anchor=文档顺序）作目录（entry.anchor gBCR 差值滚动，书签页空态文案）；
  划选/留白/矩形/套索/照片/语音经**通用 DOM 算法**天然可用（snapshotRegion null →
  无快照照常建卡），跳原文/复习/脑图/翻译/遮挡全链路复用；手写/缩放/适应宽头部
  按钮 md 隐藏（pdfOnlyActions 数组）、AI 摘录按钮不建、OCR 菜单项隐藏、
  setHandwriteMode 防御守卫、cleanupContent 复位 docKind/mdText。**限制**：不支持
  库外 md/手写/AI 摘录/OCR；md 源被编辑后归一化 rects 近似锚定漂移（挂账）。
- **EPUB 文档阅读（㊼，章=页模型）**：自研轻量渲染**不引 epub.js**——fflate
  unzipSync + 自研净化注入零新增依赖。**解析层**：`epub-xml.ts` 迷你 XML 解析器

- **渲染结构**：viewport（事件宿主，点阵背景）→ world（唯一 transform 容器：
  `translate(tx,ty) scale(s)`）→ svg 连线 + 节点 div。节点 left/top 与 SVG path **均为未缩放
  世界坐标**，天然对齐；`toWorld()` 是唯一客户端→世界换算点。
- **两个必须**：svg 视口尺寸必须覆盖全部几何——drawEdges 每次按可见节点包围盒
  （外扩 FRAME_PADDING+4）设 viewBox + CSS 尺寸；**0×0 的 svg 在 Chromium 中即便
  overflow:visible 也整体不绘制**（⑲-4 修复的连线不可见根因，v1 起连线从未显示过），
  overflow:visible 仅兜住包围盒外的描边半宽；事件挂 viewport 不挂 world（world 是
  0×0 容器收不到事件）。
- **svg 元素锚定 viewBox 原点（㉜-3）**：drawEdges 设 viewBox 后**必须同步把 svg 元素
  left/top 设为包围盒原点 (minX−PAD, minY−PAD)**——用户坐标 (x,y) 实际渲染于
  (x−vbX, y−vbY) + 元素位置；元素钉死 (0,0) 而 viewBox 随包围盒平移时，路径坐标与
  viewBox 位移相消：整图拖动（拖根节点/单根图拖任意祖先）连线在屏幕上冻结不动、
  静止时连线也带 (PAD−minX, PAD−minY) 常量偏移。修复 = left/top 跟随包围盒。

  媒体区（回填快照路径）。

## 备份（.marginpkg，㉚ v2）

- **分层**：`backup-zip.ts` 纯函数（fflate zipSync/unzipSync 组包解包 + 校验，vitest 覆盖，
  零 obsidian 依赖）；`backup-service.ts` 编排（vault/adapter/Notice 只在此层）。
- **包结构（v2）**：`manifest.json`（format/version=2/`storage:"markdown"`/计数/导出时间）+
  `notes/<数据根相对路径>`（md 树：书/未归类卡片/脑图）+ `documents/<vault相对路径>`
  （PDF 已压缩，level 0 store）+ `assets/<相对路径>`。解包校验：format、必备条目、
  zip-slip（拒 `..` 段/绝对路径/前缀不符）、version 高于当前拒绝（低于按 v1 兼容分支）。
- **导出**：先 `store.flush()` 对齐磁盘（防抖窗口内可能有未写变更），再从数据根
  collectMdFiles 收集 md 树 + assets/ 全目录；文档经 vault.adapter.readBinary 逐个读取
  （PDF 本体永远在 vault），缺失跳过计数；**库外绝对路径文档（㉞）不打包**——
  externalSkipped 单独计数（与库内缺失分开），完成 Notice 追加「库外文档 N 个未打包，
  请自行备份原文件」；记录本身保留在 md 书文件 frontmatter 的 file_path 里（跨机器
  导入后显示失联，走既有重关联）。落盘经 `backupLoc.adapter.writeBinary`
  （目录可配置，默认 `Backups/MarinMind/`）。manifest 卡片数取 `store.stats()`。
  导入侧零改动——包内永无库外文件。
- **导入顺序（关键）**：安全快照（数据根现有 md 树复制到 `pre-import-snapshot/` 目录，
  只留 1 份；同步清理旧版 `.db` 快照文件）→ **`flush(); close(); store=undefined` 之后才
  清空并覆盖数据根 md**——close 清掉防抖定时器且让 onunload 的 flush 失效，否则 reload
  触发的旧内存写回会覆盖刚导入的数据 → 文档已存在跳过（TFile 优先）、缺失的
  vault.createBinary 恢复（ensureParentFolder 递归）→ assets 覆盖写 → 桌面
  `app:reload` / 移动端提示立即重启（内存中各视图仍持旧数据快照，disable/enable 不彻底）。
- **v1 旧包兼容导入**：`parseBackupZip` 遇 `marinmind.db` 条目或 version<2 时拒绝并提示
  走兼容链路；`parseLegacyBackupZip` 解出 v1 包（库字节 + documents/ + assets/，
  校验同 v2）→ `legacyDbBytesToNotes`（库字节 → 内存 store 灌入 → 序列化 md 文件集，
  与旧库迁移共用 legacy-import 转换）→ 升级 manifest 为 v2 → **走既有 doImport 整库
  替换链路**（零新增导入语义）。空 notes（旧备份无数据）中止导入原数据不动。
- **导入入口**：隐藏 `<input type="file" accept=".marginpkg">`——可选 vault 外文件，
  比 FuzzySuggestModal 更符合备份文件的使用场景。
- **取舍**：同步 zipSync 大库卡 UI 数秒（低频操作 + Notice 预告；异步 fflate 依赖
  Blob worker，Obsidian CSP 下未验证）；Uint8Array 写盘前统一 `.slice().buffer`
  拷独立 buffer（fflate/sql.js 返回值可能共享或带 byteOffset）。

  `backfillRegionSnapshots`——为本页无 excerptRef 的 area/lasso 卡补快照后

  背景，canvas 无无损 WebP 选项，lossy 会振铃伪影）。

- **手写**：`handwrite-layer.ts` 手写激活页一 canvas 层（与 ExcerptLayer 同构），关键机制：
  - **归一化笔迹模型**（0-1 相对页面）——canvas width/height 赋值会清空内容，

## 卡片变更事件同步（⑨-B + ⑲ created；㉗ created 写库订阅上收插件级）

- **分层**：`CardEventBus`（src/events/card-bus.ts，纯 TS 零 obsidian 依赖）三个事件
  created/changed/removed；main 构造期同步创建（视图 constructor 先于 dbReady 即可订阅）；
  `CardRepository` 构造注入，**写方法内 emit**——任何调用方（视图/弹窗/未来命令）无法
  绕过通知，也不破坏"仓储零 obsidian 依赖"的分层约定。**create 双发 created + changed**
  （changed 保持跨标签同步旧语义，created 供需区分"新建/编辑"的订阅方；
  update 只发 changed）。
- **回环防护**：emit 同步执行，**契约：订阅回调禁止写库，只做 DOM/内存快照更新**——
  回调只读即无回环；写后回显统一靠事件回环（创建/编辑批注/OCR/删卡的手工 DOM 同步
  已全部删除，deleteCard 仅保留附件删除）。需写库的订阅方（摘录自动入图）必须
  queueMicrotask 延迟到 emit 返回后，且自身发出的 created 要能被自己的过滤条件拦住。
- **订阅方行为**：**main.ts `setupAutoCollect`（㉗）是唯一的 created 写库订阅方**
  ——摘录自动入图上收插件级（不依赖任何脑图视图打开，见「思维导图」章节），
  写后 refreshActiveMindmaps 通知在展视图。mindmap-view 只订阅 changed/removed：
  批注/OCR 就地改节点文本（不全量 loadMap——会重置 tx/ty/scale 平移缩放）；
  删卡 → removeNodeLocal（DB 侧 CASCADE 已删节点行，SET NULL
  上浮语义一致）。reader-view 同文档才
  处理：photo/audio 维护页角徽标数据，
  其余走 `ExcerptLayer.syncCard`（cardsById 已登记→只更新缓存；未登记→addHighlight，
  实现**跨标签新摘录互见**）；删卡 → removeHighlight + removeMediaCard；
  changed/removed 追加目录卡片数防抖重算（㉗-A）。review-view（卡组批 constructor
  订阅/onClose 退订）：removed → `session.remove` 剔除并重渲染（复习内 ⋯ 菜单与
  外部删卡同路径——含阅读器/主页/预览弹窗）；changed → `session.includes` 过滤
  （含 again 重现实例，防全库改卡风暴）后重渲染取最新；两回调零写库。
- **边界**：脑图节点结构变更（addNode/removeNode）不进事件（低频，手动刷新兜底；
  自动入图的节点由 refreshActiveMindmaps 主动推送）；备份导入整库替换不发事件。

## 区域 OCR

- **加载链**：tesseract.js 主包（API 面）经 npm 进 bundle（约 +49KB）；worker 脚本与核心
  WASM 运行时**首次使用时从 CDN 下载**（jsdelivr worker/core + tessdata 语言包，合计
  10-20MB），语言包缓存 IndexedDB 二次离线可用。`workerBlobURL:true` 让 worker 代码经
  Blob URL 装载，绕开远程 worker 脚本的 CSP 限制（Text Extractor 插件已验证该链路可行）。
  **不做离线打包**（83 决策）：首次下载后缓存本就离线可用，+30MB 包体不值。
- **版本锁（关键坑）**：`TESS_VERSION` 常量与 package.json 双处同步——CDN 资源与主包
  版本不一致时 worker 与主包消息协议不匹配，报错极难排查；升级必须双改并重测。
- **worker 语言键单例 + 串行队列（83-A）**：模块级 workerPromise 懒创建，**失败
  catch 后重置 null**（网络恢复重试不必重启）；`getWorker(langs)` 请求语言 ≠
  `workerLangs` 时 terminate 重建（getWorker 调用收进队列 job 内，语言切换天然
  串行）。**promise 链 `enqueue<T>(job)`**：所有对外 API 体内整体排队、job 落定
  吞错续链——根治模块级 statusSink 单槽互抢（连续拖框即识进度条互抢）与
  setParameters 交错。`lastPsm` 记忆跳过重复 setParameters。**85-C 会话级就绪
  登记**：`readyLangs` Set 在 promise 链 catch **之前** then 登记（失败不登记），
  `isOcrEngineReady(langs)` 供 reader-view 提示分流（同会话二次识别不再弹
  「首次需联网下载」；不持久化——wasm 每会话可能重下载，误报已就绪代价远
  小于误报需下载）；语言切换旧条目保留（IndexedDB 有缓存）。
- **PSM 版面细分（83-A）**：`pickOcrPsm(rect, 画布W, 画布H)` 纯函数启发式——
  面积占比 ≥0.5→"3" AUTO、像素宽高比 ≥6→"7" 单行、双 <100px→"8" 单词、
  其余→"6" 单块；手写路径固定 "11" SPARSE_TEXT（散落笔迹无版面结构）。
  字符串字面量类型 `OcrPsm`，service 层 `as PSM` 收窄进 tesseract 枚举
  （纯文本层不 import tesseract）。
- **逐矩形识别**：`worker.recognize(canvas, {rectangle})` 原生支持子区域，不 crop+stitch；
  **rectangle 必须用 canvas 内部像素**（width/height 属性）换算——renderTo 已按 dpr 与
  16M 像素钳制设定物理分辨率，CSS 尺寸与识别无关；换算后不足 1 像素的矩形跳过。
  `ocrCanvasRegions(canvas, rects, opts?)` 第三参 opts 化（onStatus/psm/langs——
  显式 psm 跳过启发式）。
- **整页行级识别（83-B）**：`ocrCanvasPageLines(canvas, opts?)`——recognize 第三参
  `{blocks:true, text:true}` 取版面树，`ocrLinesFromBlocks`（Block→paragraphs→lines，
  bbox 像素→归一化 DocRect clamp [0,1]，退化丢弃）出行级 {text, rect}——整页 OCR
  以 **text 卡 + 逐行 rects** 落库，复用现有多行下划线回显零新增渲染代码。
- **手写 OCR（83-D 修复错位）**：老路径渲染 PDF 原页识别，识到的是笔迹**下方
  原文**而非笔迹；现分流 `ocrHandwritingCard`——读笔迹 PNG 附件（attachments.read）
  → createImageBitmap → 合成**白底**画布（先 fillRect 白底再 drawImage——tesseract
  对透明底识别率极低）+ 2× 放大（PNG 本身 2× 导出，合计 4× 有效分辨率）+
  16M 像素钳 sqrt 回缩 → PSM 11 识别。
- **渲染隔离**：`pdf-document.renderTo` 新增 `opts.isolated`——OCR 离屏高清渲染
  （目标物理宽约 2200px，83-B 抽公共 `renderPageCanvas(page)` 供区域/整页共用）
  不取消同页在途显示渲染、也不注册 inFlight，互不抢占
  （pdf.js 允许同页并发渲染到不同 canvas）；渲染期文档被销毁时 done 静默返回，
  调用方以 `canvas.width === 0` 判定放弃。
- **文本清洗**：ocr-text 纯函数——全角空格归一、CRLF 归一、行内空白折叠、去空行
  （保留换行反映版面段落）；多矩形按顺序 \n 拼接。写入 `cards.update(excerptText)`
  （`applyOcrText` 公共尾部：区域/手写共用覆盖确认 + cardBus 回环），复习/脑图
  现有文本分支自动受益。
- **OCR→翻译流水线（83-D）**：`applyOcrText` 尾部按设置 `ocrAutoTranslate` 触发
  `autoTranslateOcr`（fire-and-forget，翻译失败与识别成功解耦）——超长前置跳过 →
  resolveEngineCall → translateText → `saveTranslationAsBlank` 落留白。
- **入口约束**：仅 area/handwriting 且有 rects 的卡显示菜单项；移动端
  `Platform.isMobile` 直接 Notice 禁用（拖框即识/整页 OCR 同守卫）；**拖框即识**
  （83-B）= createAreaCard 建卡后按设置自动 ocrCard（仅桌面 PDF）；**整页 OCR**
  = 页面右键菜单 pageByPoint 命中页才 preventDefault（docKind==="pdf" 且桌面才
  注册 contextmenu）。

## 翻译（㉔ + 83 多引擎/侧栏/折叠）

- **MN4 手册语义对齐**：核心取「内置翻译」路径——选中文字 → 翻译为目标语言
  （13 种，可切换）→ 译文**存为留白**（与原文并排对照）/ **复制**；83-E 起补
  「研究→翻译侧栏」语义（划选即时对照不建卡）。
- **引擎注册表（83-C；85-B 增有道）**：`TranslateEngineDef { id, label, mapTarget,
  buildRequest, parse, networkHint }` + `TRANSLATE_ENGINES = [google, baidu, youdao,
  deepl]`——新增引擎只需一个 def。Google 既有独立函数保留收编（存量测试零改动）；
  百度 POST urlencoded（q·from=auto·to·appid·salt·sign），**sign = MD5(appid+q 原文+salt+
  密钥)**（未编码 q，官方规范；md5.ts RFC 1321 自实现零依赖，salt 随机串在
  buildRequest 内生成、buildBaiduSign 独立导出供测试注入）；**有道（85-B）** POST
  openapi.youdao.com/api，**经典 MD5 签名 sign = MD5(appKey+q 原文全文+salt+应用
  密钥)**（与百度同构；input 截断/curtime/sha256 仅属 signType=v3 **不使用**——
  经典签名 q 不截断），errorCode 成功时不存在（存在且非 "0" 才按中文错误表报错），
  l 字段 "zh-CHS->en" 源段映射回 Google 代码，粤语/文言文 mapTarget null；DeepL
  key `:fx` 后缀自动选 api-free/api 域 + DeepL-Auth-Key 头 + JSON body。
  `resolveEngineCall (settings)` 选 def 收凭据（凭据缺失抛中文错）；`mapTarget`
  返回 null（DeepL/有道 粤语/文言文）→ translateText 抛「不支持目标语言」友好错。
- **分层**：`translate-engine.ts` 纯函数——
  `TRANSLATE_LANGUAGES` 13 语言表（Google 代码：zh-CN/zh-TW/en/ja/ko/fr/de/es/
  it/pt/ru/yue/lzh，粤语与文言文为 Google 支持的扩展代码）；
  `buildGoogleUrl`（`client=gtx&sl=auto&tl=…&dt=t` 免密钥 + 自动检测）+
  `buildGoogleBody`（**q 放 POST body urlencoded**——URL 不受长度限制，
  上限 5000 字符）；`parseGoogleResponse`（嵌套数组 `data[0][*][0]` 句段按序
  拼接、`data[2]` 为检测到的源语言，非预期结构/空译文抛错）；
  `translationAnchor`（译文锚点 = 原文最下沿矩形正下方 +0.012 间距，
  页底 `1-size` 夹取，空矩形回退页首——译文胶囊与原文并排对照的落点依据）。
- **服务层**：`translate-service.ts` 按引擎分派 spec 经 Obsidian `requestUrl`
  （**绕 CORS**，`{throw:false}` 手工判 200，桌面/移动端均可用，与 OCR 的移动端
  禁用不同）；网络不通 / 非 200 / 解析失败三类错误均转中文提示（带分引擎
  networkHint）。
- **弹窗**：`translate-modal.ts`——原文/译文对照、语言下拉**切换即重译并写回
  `translateTarget` 设置**（记住用户选择）、源语言检测徽标、「存为留白」
  （**83-F 起可选**——onSaveBlank 缺省不渲染该钮，复习手工卡场景）「复制译文」
  （无结果时禁用）、错误态带重试；`isConnected` 守卫丢弃关窗后
  过期渲染（与复习界面媒体分支同款）。`engineCall?` 可选参数缺省 Google
  （Modal 无 plugin 依赖分层不破）。
- **翻译侧栏页签（83-E）**：tocTab 扩 "translate" 三分页（syncTocTabs/
  renderTocSections 通用匹配零改动兼容）；`renderTranslateInto` 与书签页同构
  ——观感类复用弹窗 marinmind-tr-*，ttSeq 守卫跳过无关刷新（书签增删不重译），
  `runSidebarTranslate` token + isConnected 双守卫丢过期响应，凭据/网络失败
  **渲染错误态 + 重试**（侧栏常驻，非一闪 Notice）；`pushTranslateToSidebar
  (snap, {toggleOpen?})` 公共入口；划选自动刷新 `scheduleSidebarTranslate`
  500ms 防抖（百度 QPS=1 第一道闸）；**划选工具栏→侧栏（不建卡）、高亮菜单→
  弹窗（对照+存留白）双入口语义分离**；cleanupContent 清快照/计时器/token
  （防换文档旧译文误挂）。
- **复习界面翻译入口（83-F）**：topbar「翻译」钮（无 excerptText 置灰）——
  TranslateModal + engineCall；有页码定位的卡 onSaveBlank 以 translationAnchor
  建 blank 卡（与 reader saveTranslationAsBlank 同构），手工卡（page==null）
  不传 → 仅对照 + 复制。
- **译文留白折叠（83-F 轻量）**：excerpt-layer addBlankHighlight DOM 重构——
  胶囊 = `span.marinmind-blank-label`（**JS 40 字截断改 CSS ellipsis**，title
  保留）+ `button.marinmind-blank-fold`（chevron，**stopPropagation 不触发胶囊
  点击菜单**）；`blankExpanded: Set<cardId>` 会话级记忆不持久化；展开态多行
  全文（32em / 30vh 内滚动）。
- **译文落卡零新概念**：`saveTranslationAsBlank` 走 `cards.create`（blank 卡 +
  excerptText=译文 + 留白色系 + translationAnchor 锚点）——回显/多标签同步/
  自动入图全由 cardBus 事件回环承接；**无 DB 迁移、无新表新列**。
- **网络前提**：Google 需可达 translate.googleapis.com（国内需代理）；百度国内
  直连（标准版免费限 1 次/秒——侧栏防抖为此设计）；DeepL 走 api-free/api
  （免费版每月 50 万字符）。凭据明文存 data.json（设置页 desc 明示）。

## 设置与存储定位（⑩）

- **根定位抽象（ResolvedLocation）**：`{kind: "vault"|"fs", rootDir, adapter}`——数据目录与
  备份目录各一份，onload 期经 `resolveDataLocation/resolveBackupLocation` 解析缓存到
  `plugin.dataLoc / plugin.backupLoc`。**所有数据落点统一收"数据根相对路径"**
  （`书名.md`、`脑图/图名.md`、`assets/x.png`），上层（store / attachment-store /
  backup-service）只认适配器接口，仓储层零 obsidian 依赖不被破坏。默认数据目录
  `MarinMind/`（㉚ md 存储显式目录，取代旧 `.marinmind/`；旧目录常量
  `LEGACY_DATA_DIR` 仅供启动迁移检测回溯）。
- **两个适配器实现**：`VaultRootedAdapter`（vault 内，前缀拼接委托 vault.adapter；
  mkdir 按 dirSegments 逐层建——vault.adapter.mkdir 非递归且已存在抛错；list 结果剥根前缀
  归一）；`NodeFsAdapter`（桌面 vault 外，`path.resolve` 锁根防 `../` 越界逃逸、
  mkdir recursive、readBinary 独立 buffer）。
- **fs 惰性加载铁律**：`builtin-modules` 不含 `fs/promises`，必须在**函数体内**
  `typeof require === "function"` 守卫下 `require("fs")` 取 `.promises`——静态 import 的
  顶层 require 在移动端加载即崩；vitest ESM 无 require，测试内
  `globalThis.require = createRequire(import.meta.url)` 注入。
- **初始化顺序**：constructor 只留 cardBus（视图订阅契约）；onload 内
  `initStorage()`（loadSettings → resolve 两定位 → AttachmentStore）**先于**
  `dbReady = initStore()`——数据目录由设置决定，而 loadData 是异步 API；
  `dbReady` 默认 resolved 防御异常时序。resolve 失败（如移动端读到桌面同步的绝对路径
  data.json）→ 回退默认 vault 内目录 + Notice，插件保持可用。store 就绪后异步
  `detectLegacyDb()`——数据根无 md 且发现旧库时弹迁移引导（见「数据层·旧库导入」；
  vault 内旧库检测在 resolve 之前查 TFile，避免 resolve 的 mkdir 凭空建出空
  `.marinmind/` 目录）。
- **数据目录迁移（migrate-data-dir）**：设置页"暂存 + 显式迁移按钮"（防击键触发迁移与
  悬空态）。流程：前置校验 + **写探针**（写删临时文件，OneDrive/杀软锁早暴露）→
  目标已有 md 文件时 ConfirmModal 默认取消 → 停写铁律（flush → close → store=undefined
  → copyTree **整个数据根**复制——md 与 assets 皆是普通文件，不再需要 exportBytes
  权威快照）→ 失败回滚 `openAndWire` 旧位置（复制式，旧数据天然回退依据，设置值从不
  提前落盘）→ 成功最后 saveData + 桌面 `app:reload` / 移动端强提示重启。
  **旧位置保留不删**（手动确认无误后可自行删除）。
- **设置存储**：`MarinMindSettings {dataDir, backupDir, translateTarget,
  autoAddToMindmap, homeTheme（㊸ 三态 dark/light/auto）, homeDocsView,
  homeFoldersHidden（㊸ 文件夹栏收起态）, homeCardsFoldersHidden（73 卡片页卡组
  树栏收起态，镜像前者独立记忆）, excerptColors（㊹ 四工具摘录色系嵌套
  record——loadSettings 逐键归一防浅合并整块覆盖）, reviewNewPerDay（65 每日新卡
  上限，0=不限默认，钳 [0,999]）, reviewBatchSize（68 每批张数，默认 20，钳
  [5,200]——两标量直接浅合并即可，设置页「复习」小节数字输入）, selectionToolbar

## 全局文件同步与文档管理（⑩，㉚ 扩展）

- **rename 全局化**：`vault.on("rename")` 监听从 reader-view 构造器（只覆盖当前打开文件）
  移到 main.ts `registerVaultFileSync`（registerEvent 覆盖库内全部文档；目录移动时 Obsidian
  对目录下每个 TFile 逐个发事件，只处理 TFile 即天然覆盖）。**㉚ 三路分流**：改名的
  是数据根内 md（书/图文件被用户手动改名）→ `store.handleExternalRename` 跟随新路径；
  数据根外 PDF → `documents.renamePath` **先查后改返回 boolean**（原实现零行命中也
  markDirty，任意无关文件改名都触发防抖写盘写放大）。另注册 modify/delete 监听——
  仅数据根内 md 生效（`applyExternalChange` → store 回灌/移除，见「数据层·外部修改
  回灌」；删除后走 `removedCards` 事件让视图清理 DOM）；fs 数据根无 vault 事件不路由。
- **delete 刻意不全局级联**：Obsidian 删除可撤销（回收站/同步恢复），若级联
  `documents.delete` 则卡片/复习进度/脑图节点全部 CASCADE 蒸发——不可逆损失换可手动补救
  的整洁度，不划算；失联积累由文档管理面板可控清理。
- **重关联决策（planRelink 纯函数）**：失联文档在新路径重新指定时三分支——
  目标无主 → `apply`（源行直接改道）；目标已有卡片 → `reject`（宁拒不赌：同页码矩形语义
  无安全默认值，提示直接打开新文件使用现有记录，合并工具记入后续优化方向）；
  目标空行（打开即 upsert 产生的占位）→ `takeover-empty-target`（删空行后源行接管，
  单事务）。`applyRelink` 单事务落库：卡片经 document_id 外键**原地跟随源文档行**
  （id 不变零迁移零孤儿）；防御分支：目标有卡 throw 占用（此前裸 renamePath 会撞
  file_path UNIQUE 约束，测试锁定该前提）。
- **文档管理面板（DocumentManagerModal）**：命令 + 设置页入口。列表 = documents.list()
  逐行标题/路径/卡片数/徽标——就位判定 `resolvePresence` 异步五态（㉞）：库内路径
  getAbstractFileByPath instanceof TFile（ok/missing）；库外绝对路径桌面
  externalFileExists 探活（external-ok/external-missing），移动端库外不断言
  （external-unknown——fs 不可达）；「库外」徽标为中性色，区别于失联红，库外失联
  才给【删除记录】，移动端库外行无【打开】。失联行【重关联】（复用 PdfPickerModal，
  目标可库内 TFile 或库外绝对路径——targetPath 字符串统一，planRelink/applyRelink
  纯函数零改动）【删除记录】（ConfirmModal 明示级联——先
  cards.listByDocument 快照逐个 attachments.remove 清附件（发起方职责），再
  documents.delete 级联删卡片/复习/脑图节点引用）；正常行【打开】（openDoc 分流：
  库外桌面 openInReader(absPath)，移动端 Notice）。重关联与删除同款提示
  "先关闭对应阅读器标签页"（手动改路径不触发 vault rename——**库外路径永不命中
  vault 事件，改名/移动后需手动重关联**，无 fs watcher）。低频维护操作不经 cardBus
  （与备份导入一致的取舍）。

## 已知取舍

| 取舍 | 理由 | 后续 |
| ---- | ---- | ---- |
| due 快照不分页 | 一节 20 张合理，实现最简 | limit 分批 + 统计面板 |
| SM-2 而非 FSRS | ReviewState 字段已按可替换设计 | 评估 FSRS |
| 脑图连线全量重画 | 数百节点规模 O(E) 赋值足够 | 虚拟化或增量画边 |
| 脑图 DOM 而非 canvas | 可访问性/样式系统/文本渲染免费 | 规模上万节点再评估 canvas |
| 弹窗自建确认框 | ConfirmationModal 需 1.13.0（minAppVersion 1.4.0） | 升 minAppVersion 后替换 |
| vault 文件删除不级联删记录 | Obsidian 删除可撤销，级联会不可逆蒸发卡片/复习进度 | 失联积累由文档管理面板可控清理 |
| 数据目录迁移是复制不是移动 | 旧位置天然回退依据，失败零损失 | 确认无误后手动删旧目录（或后续加可选开关） |
| 重关联目标有卡时宁拒不赌 | 同页码矩形语义无安全默认值 | 跨文档卡片合并工具 |
| 备份导入/重关联/删记录不发 cardBus | 低频维护操作 + 整库替换场景 | 视图依赖 reload / 面板重渲染承接 |
| fs 模块守卫式函数内 require | 静态 import 顶层 require 移动端加载即崩 | 无（Obsidian 无官方 fs API 前的必要妥协） |
| md 存储：防抖窗口内「插件改动+手编」竞态走五字段合并 | 不静默丢数据（手编 note/text/tags/color/lineStyle 覆盖，几何/复习保内存）+ Notice 告知 | 同步盘用户注意冲突副本 |
| md 存储：查询依赖内存全量 filter | 个人规模几千卡无碍（万卡级列表过滤仍 <10ms 级） | 真有需要再加二级索引 |
| md 存储：fs 数据根不支持外部修改回灌 | vault 外路径无 vault 事件可订阅 | 手编需求用 vault 内数据目录 |
| md 存储：手删数据根 md 文件 = 删对应书/图 | 用户操作即权威（Notice 告知后果），不偷偷重建 | 回收站/版本控制可恢复 |
| sql.js 保留在 bundle（约 +1MB） | 旧库与 v1 备份导入仍需读取 SQLite | 确认迁移期过后移除 legacy 代码瘦身 |
