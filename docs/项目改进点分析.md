## 二、审查 Warning 台账（量化分级，2026-09-19 统计）

> 源数据：第三轮审查报告（v1.0.2 时点）；Warning 不阻塞，但「真实收益组」
> 修了有实际好处，其余按需。

**A 组·真实收益（建议修，一个批次可清）：**

- [ ] **window 定时器族 19 处 / 12 文件**（setTimeout 7 / clearTimeout 6 /
      setInterval 3 / clearInterval 3）：裸定时器在 popout 弹出窗口内执行时
      走主窗口计时——popout 内 UI 状态可能错窗；机械替换为 `window.setTimeout`
      等。
- [ ] **`.obsidian` 硬编码 3 处 / 1 文件**：Obsidian 配置目录名用户可改——
      换 `app.vault.configDir`，真实兼容性问题（影响面：数据目录解析）。
- [ ] **globalThis 4 处 / 2 文件**：popout 兼容，改 `window` / `activeWindow`。
- [ ] **TFile 断言 2 处**：改 `instanceof TFile` 窄化。

**B 组·零碎清理（一个批次顺手）：**

- [ ] console 非必要日志 6 处 / 3 文件（保留 console.error 诊断，删/降级
      纯 log）；不必要断言 27 处；不规则空白 2 处；await 非 Promise 2 处；
      this-aliasing 1 处；Promise-void 1 处；union 覆盖 18 处（`any`/`error`
      在联合类型里吞掉其他成员的 catch 签名类问题）。

**C 组·可选（观察）：**

- createElement → createEl **138 处 / 37 文件**：纯风格统一，量大价值低——
  官方评审对存量代码普遍放行；随文件重构顺带转，不单开批次。
- `getSettingDefinitions()` 声明式设置（1 处）：1.13+ 设置搜索可见性增强，
  涉及 settings-tab 结构性改造，收益随用户量而定。

**D 组·有据保留（答复口径，人工审核问起时用）：**

- `fetch` ×1：AI 流式回复（SSE）必需——`requestUrl` 不支持流式；非流式
  请求全部走 requestUrl，失败自动降级链已有。
- TS unsafe-* 族 **≈7400 处**（unsafe-call 3502 / member 2738 / assignment
  739 / returns 183 / passes 224）：集中在 Electron remote 窄化、requestUrl
  响应、JSON 边界等动态层的防御性最小形状断言——设计上宁窄化不 any 泄漏，
  与 Obsidian 官方示例插件的同类警告密度相当。
